# Engine sweep A: xp census of the non-combat skill scripts

Parent: rs/61 (engine exploit sweep). Slice: every `stat_advance(` in
`server/content/scripts/skill_*/**` except `skill_combat`, plus `general/` and
`tutorial/`, which is 115 call sites (393 rows once every dbrow, struct or param table is resolved to
one row per product). Read-only audit: no server, sdk or lab changes, and no lab runs
(a later child verifies the top ten).

## Conventions

- **Paths.** Script and config paths are relative to `server/content/scripts/<skill>/`
  (the skill folder is the row's skill; `general/scripts/xplamp/`, `tutorial/scripts/`,
  `login_logout/` otherwise). Engine paths are relative to
  `server/engine/src/`, under `network/game/client/handler/` for the handlers and
  `engine/` for `World.ts` and `entity/`.
- **Base xp** is the script value divided by 10 (scripts award tenths), before the
  server's 25x (`util/WorldConfig.ts:102`, `entity/Player.ts:1889`). 99 is 39,938.3 base.
- **Labels.** Every rate in the table says whether it is *read* from source, *measured*
  by a sibling issue (rs/2 for Agility, Mining, Woodcutting, Fishing and Thieving; rs/28 for
  Magic, Prayer, Firemaking, Runecraft and Smithing; rs/37 for the four helper-fed skills),
  or *inferred* from the engine rules below. Nothing in this file was measured by this
  issue.

## How the engine paces an xp action (read)

These rules turn a script's guards into the "actions per tick" column.

1. **Packet budget.** Each tick decodes at most 5 user-event packets per player
   (`network/game/client/ClientGameProtCategory.ts:6`, `engine/entity/NetworkPlayer.ts:69`).
   Only packets whose handler *succeeds* count against the 5; a packet the handler drops
   (for example because the player is delayed) is charged to the 20-packet client
   budget instead (`NetworkPlayer.ts:141-147`). Dropped packets are consumed, not
   queued.
2. **Item-on-item and item ops run inside the packet.** `OpHeldUHandler` and
   `OpHeldHandler` look up the `[opheldu]`/`[opheld]` script and execute it immediately
   (`OpHeldUHandler.ts:111-113`). They refuse only while the player is `delayed`
   (`OpHeldUHandler.ts:16`); they do not check for an open modal, and their
   `clearPendingAction()` closes any chat modal such as a level-up dialog. So **an
   item-on-item or item-op grant with no delay on its path fires once per accepted packet,
   up to 5 per tick** (inferred from the handlers; rs/37 measured it for arrows).
3. **Loc, npc and obj interactions run once per tick.** `OpLocUHandler` (and the other
   `Op*` handlers for world entities) only set an interaction (`OpLocUHandler.ts:79`);
   the script runs in the player phase of the world loop (`engine/World.ts:801`). A
   delay-free grant behind an oploc/oplocu/opnpc trigger is capped at 1 per tick, and
   later packets in the same tick overwrite the pending interaction (inferred).
4. **`p_delay(n)`** sets `delayedUntil = tick + 1 + n` (`engine/script/handlers/PlayerOps.ts:376-380`).
   Reached from a click it costs n+2 ticks (the next tick's packets are still refused);
   inside an already-running loop it costs n+1. A grant **before** the delay still lands
   on the click tick, but the next action waits out the delay.
5. **Weak-queue skilling loops** (`%action_delay` plus `weakqueue`) fire one item per
   2-3 ticks and are cleared by any modal close (`entity/Player.ts` `closeModal`). They are
   never re-triggerable within a tick.
6. **If-buttons** run only when the component is visible (`IfButtonHandler.ts`), so
   interface-driven products are gated by whatever opened the interface.

## The two known exploits in this slice: guards confirmed

- **Wine fermentation (Cooking).** The grant is in the `[timer,fermenting_wine]`
  script (`skill_cooking/scripts/cooking_inv/scripts/wine/wine.rs2:22-70`) and has no
  Cooking check: it ferments every jug of unfermented wine in the bank (15 batches of
  floor(n/15), each batch sharing one `stat_random(cooking,48,352)` roll, then the
  remainder singly) and in the inventory, at 110 base each (`wine.rs2:35`, `:49`,
  `:63`). The timer is armed for 20 ticks by squeezing grapes (`wine.rs2:20`) and on
  every login (`login_logout/login.rs2:70` calls `~ferment_wines_login`,
  `wine.rs2:72-73`). The only level check is the 35 Cooking needed to *squeeze* grapes
  (`wine.rs2:8`), which the helpers do. Confirmed as described in rs/37.
- **Bury (Prayer).** `[opheld1,_bones]` (`skill_prayer/scripts/bury_bone.rs2:1`) runs
  `p_stopaction; p_delay(0)` (`bury_bone.rs2:8-10`) *before* deleting the bone and
  granting (`bury_bone.rs2:13-15`). `OpHeldHandler` drops every OPHELD while the player is
  delayed, so a second bury in the same or the next tick is lost: hard 2 ticks per bone,
  as rs/28 measured. Confirmed.

## Candidates worth verifying

Compared against the current route rate for each skill (rs/37 for Fletching, Cooking,
Herblore and Crafting; rs/2 and rs/28 for the rest). **No row in this slice beats a
current route outright.** The gathering, Agility, Thieving, Smithing, Magic, Runecraft,
Prayer and Firemaking routes are already the top row of their skill here, at the measured
rate. What is worth a lab run:

1. **Battlestaves as the Crafting fallback.** Orb on battlestaff
   (`battlestaves.rs2:15-38`) is delay-free with the level checked, and the air battlestaff
   gives 137.5 base at 66, exactly the dragonstone's 137.5 (`battlestaves.struct:13-17`,
   `gem.dbrow:64-67`). Water (54, 100), earth (58, 112.5) and fire (62, 125) all beat the
   diamond fallback (107.5 at 43). Where dragonstones run short, battlestaves keep the
   route at 687.5 base per tick (inferred). Verify: the 5-per-tick burst with orb on
   battlestaff, and supply (battlestaves from shops, orbs from helpers casting Charge Orb or
   from the GE; rs/68 economy census).
2. **Ugthanki kebab as the Cooking fallback.** No Cooking check anywhere on the path
   (`ugthanki_kebab.rs2:73-135`), delay-free, 120 base per kebab, 100% success from about
   37 (`stat_random(cooking,118,492)`, `:127`). About 600 base per tick (inferred), so 1->99
   is about 67 ticks of packets plus supply cycles: slower than wine (~47 ticks in one
   login) but independent of the login timer. Supply is heavy (pitta, tomato, onion,
   cooked ugthanki meat, bowl) and the mixture steps cost three more packets per kebab
   unless helpers make the mixture (they need no level either).
3. **Magic potion in the Herblore band 76-78.** 172.5 base at 76 (`brew_potion.struct`
   row `3dose1magic`) beats the ranging potion (162.5) the route uses there. Worth about 6%
   of that band; only if potato cactus is available (rs/68).
4. **Level-up dialogs during item-on-item bursts.** By rule 2, the next OPHELDU packet
   closes a level-up chat dialog (`clearPendingAction` -> `closeModal`) and still runs, so a
   delay-free burst should not stall on level-ups. rs/37 notes that level-up dialogs stall
   loops; if a burst measurably stalls, rs/67 should find out why. Applies to all four
   rs/37 routes.
5. **Genie lamps.** 10 x the current base level per lamp (`xplamp.rs2:110-111`), 990 base
   at 99, about 2.5% of a 99, with no delay. Lamps come only from the genie random event,
   so this is a supply question for rs/65 and rs/68 (whether the macro events that
   `afk_event` spawns can be farmed), not a route.

Rows that look large but are not candidates: the gnome cocktail (300 per tick, no level
check) and kebab both lose to wine; rune darts (188 per action at 81) tie rune arrows
(187.5 at 75); bow stringing peaks at 457.5 per tick; hard leather (175) and snelms
(162.5) lose to gems at every level; lock-picking doors peaks around 8 per tick (best door
at 99) against the knights' 17.3.
